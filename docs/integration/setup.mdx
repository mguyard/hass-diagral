To configure the integration, you'll need your Diagral credentials - the same ones used for the Diagral eOne mobile application.
The `Diagral` integration communicates with the Diagral Cloud.

<Warning>
Please be aware that the Diagral alarm system is a security system, and for security reasons, you may want to consider carefully before connecting it to the Home Assistant automation platform.
Neither the developer of this integration nor the [`pydiagral`](https://github.com/mguyard/pydiagral) library can be held responsible for any issues that may arise from using this integration or the [`pydiagral`](https://github.com/mguyard/pydiagral) library.
Users install and use this integration at their own risk and with full understanding of the potential implications.
</Warning>

## Requirements

1. A working Diagral Alarm system
2. A Diagral connectivity box (DIAG56AAX (End of Sales) or a [DIAG59AAX](https://www.diagral.fr/2026/01/19/nouvelle-centrale-dalarme-ip-4g-diagral-diag99agx/) available inside DIAG99AGX)
3. An active Diagral eOne mobile application account
4. Internet connectivity for your Home Assistant

## Required Information

You'll need just a few details to configure the Diagral integration:
- Your Diagral username (email address)
- Your account password
- The PIN code of your central — each central has its own
- Your system serial ID (from the DIAG56AAX/DIAG59AAX box), only if the centrals of your account cannot be listed during setup

### Finding Your System Serial ID

The serial number is located inside your Diagral box.
To access it, open the box and locate a label with a QR code.
You'll find a 14-character code - this is your box's serial number.

<Image src="https://raw.githubusercontent.com/mguyard/pydiagral/main/docs/how-to-find-diagral-serial.png" alt="Location of System Serial ID"/>

<Info>
For guidance on opening the box, refer to the official DIAG56AAX/DIAG99AGX documentation provided with your device.
</Info>

## Integration Setup in Home Assistant

The setup takes a few minutes and is done from the Home Assistant interface.

<Warning>
As [only one simultaneous connection is allowed by the Diagral API](/faq#session-already-opened), before starting the integration setup, make sure you don't have any other active connections such as with the Diagral eOne mobile application.
</Warning>

<Steps>
  <Step title="Start the setup">
    Click the button below:

    [![Open your Home Assistant instance and start setting up a new integration.](https://my.home-assistant.io/badges/config_flow_start.svg)](https://my.home-assistant.io/redirect/config_flow_start/?domain=diagral)

  <Step title="Enter your Diagral credentials">

  <Step title="Choose your central and enter its PIN code">
    The centrals of your account are listed; those already in Home Assistant are not. Each central has its own PIN code.

    <Image src="/images/configflow-step2.png" alt="Step 2 - Diagral Central and PIN Code" />

    If the centrals of your account cannot be listed, this step asks for your `Serial ID` instead — see [Finding Your System Serial ID](/integration/setup#finding-your-system-serial-id).
  </Step>

## Options

You can customize your integration experience through various options.

### Alarm Panel Options

The Alarm Panel options allow you to specify whether a code should be required when using the Alarm Control Panel UI:

| Option | Code required |
| --- | --- |
| Never | For no action |
| Disarm Only | Only to disarm |
| Always | To arm and to disarm |

<Image src="/images/alarm-control-panel.png" alt="Alarm Control Panel" />

<Info>
Keep in mind, if you switch to `Never` the code will be also automatically removed.
</Info>

### Emergency mode

If the usual Diagral cloud service (Emerald) is degraded, an existing integration can use the alternative Topaze service for its central configuration, state and whole-system commands. Open **Settings > Devices & services > Diagral > Configure** and enable **Use emergency mode**. This reloads the entry. Disable the same option to return to normal mode; there is no automatic switch between services.

Normal mode remains the default. Emergency mode requires a version of `pydiagral` that provides `TopazeDiagralAPI`; if the installed library does not support it, the options form asks you to update the integration. Initial account setup and reconfiguration still require Emerald.

| Feature | Service in emergency mode |
| --- | --- |
| Central configuration and state | Topaze, preserving the existing Home Assistant central identity |
| Whole-system arm, disarm and presence | Topaze; a command is sent once and confirmed by a state read |
| Group commands, detailed anomalies and webhook management | Emerald; these may remain unavailable during its outage |
| Intrusion events | The existing webhook; Topaze polling does not replace event delivery |

Configuration metadata is cached for one hour. Session cleanup is attempted after each use, and emergency mode does not take over another active session. Topaze is another cloud service, so internet access is still required. Its connection limits are not documented here; repeated manual refreshes or commands can exhaust the service quota.

The **Fallback API** diagnostic reports whether the last central refresh succeeded through Topaze. **Diagral cloud reachable** continues to measure the Emerald ping independently. A green fallback diagnostic therefore does not prove that detailed anomalies or webhook delivery are working.

When a webhook verification request fails temporarily, the integration preserves its local receiver only if the saved webhook ID and exact URL fingerprint prove that the receiver belongs to this entry. The repair remains until registration is confirmed. No subscription is taken over or reported as healthy solely because emergency polling works.
