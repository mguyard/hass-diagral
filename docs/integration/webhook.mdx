The Diagral cloud supports sending webhooks to your Home Assistant to receive real-time alerts, anomalies, or state changes.
Notifications are transmitted per system, and **each system can have only one webhook subscription.**

Webhooks update Home Assistant between regular cloud refreshes:
* `STATUS`: A status change (armed, disarmed, etc.) triggers a cloud refresh.
* `ALERT`: An alert, such as intrusion or silent panic, updates the alarm panel and publishes an event directly.
* `ANOMALY`: A new anomaly triggers a cloud refresh.

## Home Assistant URL

To benefit from webhooks, you need a Home Assistant instance that is `accessible from the Internet over HTTPS`.

[![Open your Home Assistant instance and manage your systems network configuration.](https://my.home-assistant.io/badges/network.svg)](https://my.home-assistant.io/redirect/network/)
<Image src="/images/external-access.png" alt="External Access Configuration" />

The integration can use the connection through Home Assistant Cloud provided by [Nabu Casa](https://www.nabucasa.com).

However, if you have both an external access and a Home Assistant Cloud subscription, priority will be given to external access (if both access methods meet the prerequisites mentioned at the beginning of this section).

## Implementation

Webhooks are set up automatically in the background when the integration starts. Cloud polling remains active if registration fails. The webhook identifier is persisted in the config entry and the local handler is registered before enabling the remote subscription.

Use the [Instant Notifications and Last Notification Received diagnostic sensors](/integration/entities#connection-diagnostics) to check registration and delivery. Callback URLs contain a secret identifier and are not written to logs.

After a failed registration, retries are scheduled after 30, 60, 120, 300 and 900 seconds. If all attempts fail, the status becomes `retry_exhausted`. The error category is available in the diagnostic sensor attributes and logs.

<Info>
After resolving an error, reload the integration or use [diagral.register_webhook](/integration/actions#register-webhook) to retry. [diagral.unregister_webhook](/integration/actions#unregister-webhook) cancels pending retries and removes this entry's handler and subscription when ownership is confirmed.
</Info>

## Existing subscription

Your Diagral system (serial ID) can send its events to a single URL only. When the integration starts, it checks who that URL belongs to:

- **This Home Assistant** — for example after a change of your external URL, or after switching between Home Assistant Cloud and a direct external access: the subscription is updated to the new URL, without any action from you.
- **Another installation** — another Home Assistant, a test instance, or another system using the Diagral webhook: the integration leaves it untouched, because overwriting it would silently stop that installation from receiving events.

The config entry stores a SHA-256 fingerprint of the URL it registered. The integration compares the current subscription against that fingerprint to recognize its own subscription even after its external URL changes. For older entries without a fingerprint, the initial ownership check accepts an identical URL, or direct Home Assistant webhook URLs with the same scheme, host and port and a path beginning with `/api/webhook/`. A shared Nabu Casa hostname alone does not prove ownership.

If the subscription belongs to another installation, the diagnostic status becomes `conflict`, a repair appears in **Settings > System > Repairs**, and a warning is written in the logs. Until it is solved, Home Assistant does not receive webhooks: the alarm state is still refreshed every `5 minutes`, but intrusion alerts (the `triggered` state) and `DIAGRAL_EVENT` events do not arrive.

To make this Home Assistant receive the events, open the repair and confirm, or call the [diagral.register_webhook](/integration/actions#register-webhook) action. The other installation then stops receiving them.

<Info>
Disabling, reloading or removing the integration only deletes the subscription if it belongs to this Home Assistant. A subscription owned by another installation is never deleted.
</Info>

On reload, the worker is cancelled and the local handler and API session are released. The Nabu Casa cloudhook mapping is retained to preserve its URL; explicit unregistration or removal of the integration removes the mapping.
