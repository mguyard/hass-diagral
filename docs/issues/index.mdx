## Collect Issues information

### Diagnostic File

On the device info page for the device entity, you will see a "Download Diagnostics" button.
Make sure you upload this to your GitHub issue.

The file tells whether the Diagral cloud answers, the state of the webhook, the hardware, and what Diagral sends — the last notifications and the structure of its answers — without your credentials, your serial nor your names.

<Image src="/images/diagnostics.png" alt="Diagnostic" />

<Warning>
All confidential information is REDACTED, but please verify before uploading the file to your GitHub issue.
</Warning>

To understand what the file tells, starting from the problem you observe, see [Reading the diagnostics](/issues/diagnostics).

### Debug Logging

When logging a bug, always ensure you send us the debug logs. How to enable them depends on whether the integration is already set up:

<Tabs>
  <TabItem label="The integration is set up" value="ui">
    Enable debug logs from the integration page within Home Assistant:

    <Image src="/images/debugging.png" alt="Enable debug logging" />

    When you disable debug logs through the interface, the integration logs are automatically downloaded. The debug logs also appear in the standard Home Assistant logs.
  </TabItem>
  <TabItem label="The setup fails" value="yaml">
    Enable logs in your `configuration.yaml` file by adding the following, then restart Home Assistant:

    ```yaml title="configuration.yaml"
    logger:
      default: info
      logs:
        custom_components.diagral: debug # [!code highlight]
    ```
  </TabItem>
</Tabs>

<Card title="Active debug on pydiagral library" icon="spider">
For a more detailed insight into the issue, you can also enable debugging for the `pydiagral` library.
```yaml
logger:
  default: info
  logs:
    custom_components.diagral: debug
    pydiagral.api: debug # [!code highlight]
```
</Card>

### Warnings about Diagral data

The `pydiagral` library checks every answer of the Diagral cloud. When a field it expects is missing or malformed, it keeps working without it and writes a warning, once per field:

```logs
WARNING (MainThread) [pydiagral.models] Diagral sent Webhook data whose webhook_url field is missing. Please report it at https://github.com/mguyard/pydiagral/issues, with your pydiagral version, so the model can be fixed
```

Please report it as the message asks: Diagral changed its data, and the library needs to follow.

It also warns once when your installation uses a feature built from the Diagral documentation only, such as cameras or automatisms, which could not be checked on a real installation.

In both cases, attach the [diagnostics file](/issues#diagnostic-file) to the issue rather than copying log lines: it lists every such field since Home Assistant started, including keys the library does not know, which it does not write in the logs.

A webhook notification Diagral sends without its date, system ID or alarm code cannot be used. It is ignored, and the reason is written in the logs:

```logs
ERROR (MainThread) [custom_components.diagral.webhook] Ignoring an invalid Diagral webhook: Webhook date_time must be an ISO date string
```

## Declare issue

<Steps>
  <Step title="Collect the information">
    Download the [diagnostics file](/issues#diagnostic-file) and, if possible, reproduce the problem with the [debug logs](/issues#debug-logging) enabled.
  </Step>
  <Step title="Open an issue">
    [Open a GitHub issue](https://github.com/mguyard/hass-diagral/issues/new/choose), choose the form that fits, and fill it in: it asks for everything needed to resolve the problem as quickly as possible.
  </Step>
  <Step title="Attach the files">
    Drag and drop the diagnostics file and the logs into the issue, after checking them.
  </Step>
</Steps>

<Warning>
Logs may contain confidential or personal information (alarm name, system ID, user name, Home Assistant URL, etc...). Therefore, it is essential that you verify the content of all logs/files that you share.
</Warning>
